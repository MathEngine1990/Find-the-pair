# Публикация «Найди пару» в Одноклассниках

Подготовлено 4 ноября 2026. Код адаптирован для современного запуска через VK Bridge
с параметром `vk_client=ok`. Это техническая подготовка, не заключение о юридическом
соответствии и не подтверждение прохождения модерации. Публикация не выполнялась.

## Локальная проверка и сборка

В папке проекта: `npm test`, затем `npm run build`.
Результат — папка `dist`, готовая для статического HTTPS-хостинга, в том числе
в подпапке сайта. Загружать её содержимое, с index.html в корне размещения.
Сборка сохраняет порядок обычных скриптов и локальный Phaser; не требует установки
зависимостей для самой сборки. Архивные assets/old и резервные .bak не включаются.
`npm run dev` использует установленный Vite. Параметр `?vk_client=ok` позволяет
проверить ветвление интерфейса локально, но не подтверждает работу SDK и рекламы.

## Что подготовлено

- Общая кодовая база для VK и ОК, без старого FAPI.
- Ключи прогресса ОК отделены по платформе, приложению и пользователю. Старые ключи VK сохранены.
- Реклама только после завершения партии перед результатами. Длительность и закрытие определяет SDK.
- Для ОК реклама запрещена первые 30 секунд каждого запуска — более строго, чем правило
  первых 30 секунд после установки. Нельзя снять этот минимум настройками частоты.
- Проверка активности страницы и событий Bridge до запроса и после проверки доступности.
- Отказ SDK, отсутствие рекламы и неподдерживаемая платформа не блокируют итоги.
- Частота задаётся в utils/AdsConfig.js. Нулевые ограничения не означают согласованную
  платформой частоту: перед выпуском проверьте актуальные условия кабинета.
- При таймауте показа результаты освобождаются, но повторный показ и восстановление
  звука ждут ответа SDK, поскольку отменить уже отправленный показ нельзя.
- Публичная ссылка для обмена результатом не содержит параметров запуска и подписи.

## Перед отправкой на модерацию

1. Использовать кабинет VK Mini Apps: с 26 ноября 2025 новые игры ОК регистрируются
   через него. Уточнить в кабинете способ подключения ОК для уже существующего VK-приложения.
   Не создавать приложение старым способом через ok.ru и не подменять рабочую игру VK.
2. Получить отдельный тестовый HTTPS-адрес для feature/newera. Ветка Git сама по себе
   адреса не создаёт. Не менять production URL до проверки. На сервере не должно быть
   X-Frame-Options:SAMEORIGIN/DENY, запрещающих iframe ОК; проверить фактические заголовки
   и разрешённые frame-ancestors по актуальным инструкциям кабинета.
3. Заполнить utils/OKReleaseConfig.js: публичная ссылка ОК, группа поддержки (почта необязательна),
   владелец игры. Это публичные данные, не место для секретов.
4. В privacy-policy.html и user-agreement.html уже указаны ИП Воробьев Анатолий Сергеевич
   и группа поддержки. До публикации проверить полноту сведений об операторе, цели и основания
   обработки, состав данных, сроки хранения, порядок удаления и контакты. Упомянуть ОК,
   SDK и рекламу. Проверить соответствие фактической обработке и применимому законодательству
   с профильным специалистом; существующая отметка 0+ требует проверки контента и рекламы.
   Согласовать текст внутриигрового соглашения и версию согласия с документами.
5. Выполнить `npm run release:check`. Пока публичная ссылка и обязательные поля не заполнены, команда
   намеренно завершается с ошибкой. Успех проверяет заполнение, не законность текста.
6. Проверить права на картинки, шрифты, музыку; возрастную маркировку, описание, русскую
   локализацию, оригинальные иконки и размеры изображений по текущей форме кабинета.
   Создать/подключить группу игры и канал поддержки. Не использовать чужие персонажи
   и рекламные материалы без прав.
7. Подключить монетизацию в кабинете, оформить сведения о получателе выплат и принять
   применимые оферты самостоятельно. Использовать только разрешённую рекламу платформы;
   не добавлять стороннюю рекламную сеть, искусственные показы или собственную кнопку пропуска.
8. Проверить в реальной оболочке ОК на web/Android/iOS, доступных для публикации:
   первый запуск/отказ от соглашения, загрузка всех тем, вся партия, сохранение и повторный
   вход, достижения, несколько партий подряд, отсутствие рекламы, закрытие/ошибка рекламы,
   сворачивание во время проверки/показа, звук после возврата, разные пользователи, отсутствие
   обмена прогрессом между VK и ОК. Для платформ без поддерживаемого NativeAds итоги идут без рекламы.
9. Отправить на модерацию через кабинет. Только после проверки объединять ветку с main
   и менять адрес рабочей версии. Прохождение автоматических тестов не заменяет модерацию.

## Зависимости

package.json согласован с существующим package-lock.json (Vite 7.1.5 в lock-файле).
Phaser загружается из lib/phaser.min.js, VK Bridge — через загрузчик в main.js;
дублирующие неиспользуемые npm-зависимости удалены. Для разработки используйте
версию Node.js, поддерживаемую установленным Vite; проверки выполнены на Node.js 24.19.0.
